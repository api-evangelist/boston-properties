# BXP (Boston Properties)

> BXP is the largest publicly traded developer, owner and manager of premier workplaces in the
> United States — a self-administered REIT operating Class A office, life science and mixed-use
> property across Boston, Los Angeles, New York, San Francisco, Seattle and Washington DC.
> BXP runs no developer program. This file was generated by API Evangelist from the company's
> public surface on 2026-09-04; https://www.bxp.com/llms.txt returns HTTP 404.

## What is callable

BXP publishes no API product, no developer portal, no SDK and no documentation. The one
machine-readable contract it serves is the stock WordPress REST API on its corporate website —
incidental CMS infrastructure, not an offering. It is anonymously readable and undeclared:
there are no terms attached to programmatic use of it, no rate limits are signalled, and
responses carry `x-robots-tag: noindex`.

- [WordPress REST API route index](https://www.bxp.com/wp-json/): the provider-served discovery
  document — 332 routes across 15 namespaces, HTTP 200.
- [Search site content](https://www.bxp.com/wp-json/wp/v2/search): full-text search over pages
  and posts.
- [Pages](https://www.bxp.com/wp-json/wp/v2/pages): 20 published pages, anonymous read.
- [Categories](https://www.bxp.com/wp-json/wp/v2/categories): content taxonomy.
- [Content types](https://www.bxp.com/wp-json/wp/v2/types): what this site exposes to REST.
- [oEmbed provider](https://www.bxp.com/wp-json/oembed/1.0/embed?url=https://www.bxp.com/):
  oEmbed 1.0, HTTP 200.

## What is NOT callable

The things an agent would actually want from BXP are not in the API. Properties, regions,
team members, property types and member types exist on the site as custom post types — each has
its own XML sitemap — but none is registered for REST. There is no leasing, availability,
tenant, or building-systems API. Writes and privileged reads require a WordPress account on
BXP's own site and are not obtainable by a third party.

- No OpenAPI, GraphQL, gRPC, WSDL or AsyncAPI document is published by BXP.
- No MCP server. The WordPress Abilities API namespace is registered but auth-gated (401).
- No agent card at /.well-known/agent-card.json or /.well-known/agent.json on any BXP host.
- No security.txt, no OAuth or OIDC discovery document, no /.well-known/api-catalog.
- No status page, no changelog, no deprecation policy, no SLA, no support channel for developers.
- No SDKs or CLI on npm, PyPI, Maven, NuGet, RubyGems, crates.io or pkg.go.dev.
- No public GitHub organization.

## Operating notes for an agent

- Present a browser-shaped `User-Agent`. Cloudflare answers a default agent User-Agent with an
  HTML 403 interstitial ("Attention Required! | Cloudflare") on every route, including routes
  that return 200 to a browser.
- `robots.txt` sets `Crawl-delay: 10` and disallows nothing.
- Pagination is `page` / `per_page` (max 100) with `X-WP-Total`, `X-WP-TotalPages` and an
  RFC 8288 `Link: rel="next"` header.
- Errors are the WordPress envelope `{code, message, data.status}` — not RFC 9457 problem+json.
  Observed codes: `rest_invalid_param` (400), `rest_no_route` (404), `rest_post_invalid_id` (404),
  `rest_forbidden` (401), `rest_cannot_view_themes` (401).
- There is no idempotency mechanism and no dry-run mode.
